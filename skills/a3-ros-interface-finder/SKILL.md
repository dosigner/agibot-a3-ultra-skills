# A3 Ultra ROS/API 찾기

검토용 초안이다. 기능 설명을 정확한 인터페이스 식별자와 원문 절로 연결한다. 색인의 문서 기록과 실제 장비에 존재하는 인터페이스는 별도로 검증한다.

설치 경로가 심볼릭 링크이면 먼저 `SKILL.md`의 실제 경로(realpath)를 확인하고 모든 상대 참조와 명령 경로를 실제 경로 기준으로 해석한다.

## 검색 절차

1. 사용자가 원하는 기능과 읽기/명령 의도를 확인한다. 정확한 이름이 주어지면 먼저 그대로 찾고, 기능명이라면 관련 후보를 반환한다. 한국어 검색어와 API 이름을 임의로 일대일 대응하지 않는다.
2. `catalog.json`의 `interfaces`를 검색한다. CLI를 사용할 때 아래 명령은 이 `SKILL.md`가 있는 디렉터리에서 실행한다. 다른 작업 디렉터리에서는 스킬 위치를 기준으로 스크립트의 절대 경로를 계산한다.

```bash
python3 ../../scripts/find_interface.py "팔 관절"
```

3. 후보의 `source_url`을 열어 실제 H1/H2/H3 절과 인터페이스 표를 읽는다. `transport`, 메시지 타입, 입력/출력 방향과 예제 경로를 원문에서 대조한다. 이름이 비슷한 조회 API와 상태 변경 API를 구분한다.
4. 이름, URL 또는 타입이 충돌하면 양쪽 표기와 출처를 함께 반환한다. SDK의 프로토콜 정의와 예제를 다음 근거로 조사한다. 근거 없이 이름을 수정하거나 조회처럼 보이는 요청을 실행해 정답을 알아내지 않는다.
5. 실제 장비 확인이 요청 범위에 포함되면 대상 보드와 설치 버전, ROS 환경을 먼저 확인한다. `ros2 topic list -t`, `ros2 topic info -v`, `ros2 interface show` 같은 읽기 전용 조회로 존재, 타입, 발행자/구독자와 QoS를 대조한다. Topic 조회만으로 RPC나 물리 동작이 검증됐다고 표시하지 않는다.

## 결과 형식

| 필드 | 반환할 내용 |
| --- | --- |
| 정확한 식별자 | 원문에 있는 Topic 이름 또는 RPC 서비스/메서드 |
| 전송 방식과 역할 | ROS 2 Topic / HTTP JSON RPC, 발행/구독 또는 요청, 상태/명령 구분 |
| 타입과 데이터 | 메시지 타입, 필요한 필드와 단위. 확인되지 않은 항목은 미확인 |
| 적용 조건 | 문서 버전, 대상 호스트/보드 근거, 모드, 제어권, QoS, 주기, 시간 제한과 해제 동작 |
| 코드와 출처 | 실제 SDK 예제 경로, 존재가 확인된 GitHub 파일, 해당 원문 헤더 주소 |
| 검증 상태 | 문서 확인 / SDK 대조 / 장비 조회 / 실행 관측 중 실제 수행한 것과 불일치 |

결과가 없으면 색인 범위와 검색어를 밝히고 공식 목차와 원문을 추가 탐색한다. 미발견을 곧바로 미지원이라고 단정하지 않는다. 외부 검색에는 제품명, 공개 식별자, 일반화한 오류만 사용하고 개인 로그나 자격 증명을 전송하지 않는다.

이 스킬의 완료 조건은 출처가 있는 정확한 후보 또는 근거가 부족한 이유를 전달하는 것이다. 검색 자체는 Topic 발행, RPC 실행, 서비스 중지나 설정 변경을 수행하지 않는다. 사용자가 후속 실행을 요청하면 해당 기능의 제어 절차와 이미 정한 권한 범위를 따른다.
