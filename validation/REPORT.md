# A3 Ultra 스킬 가이드 초안 검증

검증일: 2026-11-17 KST

## 결과물과 범위

- `index.html`: 초보자, 인터페이스, 하드웨어, ROS/API 검색 가이드와 원문 목차를 연결하는 단일 로컬 HTML.
- `skills/`: 네 종류의 검토용 스킬. 최초 초안 검증 시점에는 전역 스킬 설치 또는 자동 활성화를 수행하지 않았다. 이후 묶음 설치 검증은 별도로 기록한다.
- `catalog.json`: 공식 영문 v3_3 개발 가이드 20페이지, 실제 H1/H2/H3 주소 173개, 표 기반 인터페이스 출현 항목 121개.
- 121개 항목은 ROS2 Topic 59개, HTTP JSON RPC 56개, RPC 4개, ROS2 Service 2개로 구성된다. 서로 다른 절에 같은 식별자가 반복될 수 있으며 고유 런타임 API 개수가 아니다.
- `references/related-links.json`: 확인한 Git 커밋으로 고정한 GitHub 파일 링크 3개.

## 실제로 수정한 검색 문제

팔 상태를 검색할 때 공동 절 제목의 State와 명령 메시지 타입 JointState 때문에 팔 명령 Topic까지 후보에 포함됐다. 이름과 기능 설명의 일치를 우선하고, 해당 후보가 없을 때만 헤더와 타입을 보조 검색하도록 바꿨다. 현재 팔 상태 검색은 상태 Topic의 두 출처를 반환하며, 팔 강성 검색은 Kp/Kd 설정을 설명하는 별도 팔 명령 Topic을 반환한다. 두 경우를 회귀시험에 포함했다.

## 독립 스킬 행동 평가

1. 팔 compliance 상태 조회 요청: 원문 7.1.13의 CheckArmCompliance 이름과 DisableArmCompliance URL 충돌을 확인했다. 잘못된 URL을 조회 예제로 제시하거나 실행하지 않았다. SDK 예제 실파일은 확보되지 않아 확정된 HTTP 호출 예제는 미검증으로 남겼다.
2. 서비스함 USB-C 카메라 연결 질문: 원문 9장 2.3의 리모컨 충전 전용 조건을 찾아 연결 가능으로 안내하지 않았다. 가슴 내부의 다른 USB-C와 GMSL 포트는 별도로 구분했다.

두 평가에서 장비 접속, Topic 발행, RPC 실행, 서비스 변경은 수행하지 않았다. 이 평가는 제한된 두 시나리오의 행동 확인이며 모든 요청에 대한 정확도를 보장하지 않는다.

## 남은 한계

- 이 색인은 구조화된 인터페이스 표, Topic 목록, 예제 표를 수집한다. 본문 문장이나 코드 블록에만 있는 이름은 추가 원문 탐색이 필요하다.
- 표에 메시지 타입이 없거나 추출 근거가 부족하면 빈 목록을 유지한다. 이는 미지원 판정이 아니다.
- 공식 문서의 보드/IP 대응, compliance URL, 일부 IMU 타입 표기 등 불일치는 원문을 임의로 고치지 않고 확인 대상으로 남겼다.
- 문서, 검색 캐시와 GitHub 기본 브랜치는 바뀔 수 있다. 카탈로그 수집 시각과 Git 커밋을 기준으로 재확인해야 한다.
- 이 묶음의 공유 파일과 스킬 간 상대 경로를 함께 유지해야 한다. 각 SKILL.md 파일만 따로 복사한 설치는 검증하지 않았다.
- 실제 A3 Ultra의 SDK 정의, 설치 버전, ROS 그래프, 카메라/LiDAR 데이터, 하드웨어 배선, 크레인 제동은 검증하지 않았다.
- 기존 논의의 외부 고정센서와 A3 탑재센서 선택, 크레인 제어 정책, 자동 복구 범위는 이번 초안에서 정하지 않았다.

- 사용자가 합의한 12개 스킬 구성, 작성된 네 초안과 미작성 여덟 항목을 README와 트리맵에 구분했다.
- 내장 image_gen으로 설명 그림 세 장을 생성하고, 구조와 수치를 근거 자료와 대조했다. 총괄 스킬 수의 중복 표기와 관절 그림 범례를 수정했다. 최종 이미지와 생성/수정 프롬프트를 저장소에 포함했다.
- 관절 모델의 95 links / 94 joints / 63 revolute / 31 fixed / 12 mimic 집계를 XML 파서와 독립 Expat 집계로 대조했다. 원본 세 모델 파일이 확인한 Git 커밋의 blob과 바이트 단위로 일치함을 확인했다.
- GitHub Markdown API가 README의 제목 16개와 그림 세 개를 HTML로 렌더링하는 것을 확인했다. 이 API 결과에는 자동 heading ID가 없어 실제 GitHub 페이지의 목차 스크롤 동작까지 검증한 것은 아니다.
- 당시 Markdown 상대 링크와 이미지 파일 58개가 패키지 내부의 실제 파일로 이어짐을 확인했다. 당시의 개별 설치 예시는 로컬 파일 링크를 추가하지 않았다.
- NVIDIA 공식 live catalog에서 관련 후보 세 개의 SKILL.md를 확인했다. 이 후보 조사 시점에는 설치와 장비 접속을 하지 않았다.
- architecture.md의 Mermaid 다섯 개는 원문 구조를 검토했으나 실제 Mermaid 렌더러 실행은 안 돌려 봤음. README의 그림 세 개와 텍스트 트리는 직접 확인했다.

## 묶음 설치 검증

사용자가 A3 초안 4개와 NVIDIA 공식 스킬 3개의 동시 설치를 승인했고, macOS의 현재 Codex 환경에서 실행했다. 설치 위치는 기본 Codex skills 디렉터리이며 개인 절대 경로는 이 보고서에 기록하지 않는다.

- `--check`의 읽기 전용 사전 검사 후 A3 네 개는 체크아웃 링크, NVIDIA 세 개는 공식 helper의 SHA archive 다운로드로 설치했다.
- NVIDIA 출처는 `NVIDIA/skills`의 커밋 `2371df31af392071effa2bd82f39aa98b130e428`이다. 설치된 세 `SKILL.md`를 해당 커밋의 원문과 바이트 단위로 대조해 일치를 확인했다.
- 설치된 A3 검색 스킬의 realpath를 기준으로 공통 색인을 읽고, 팔 상태 Topic의 두 문서 출처를 반환하는 것을 확인했다.
- 설치 명령을 다시 실행해 같은 A3 링크가 재사용되고 NVIDIA 파일 38개의 해시가 바뀌지 않는 것을 확인했다. 재실행 시 기존 NVIDIA 출처는 스크립트 자체에서 재검증하지 않으므로 `existing_unverified`로 표시하며, 위의 별도 원문 대조와 구분한다.
- 회귀시험은 읽기 전용 검사, 공통 자료 접근, 다른 디렉터리와 끊어진 링크 보존, 외부 설치 실패 시 A3 링크 미생성, 이름 경로 이탈 거부, 기존 NVIDIA 파일 보존, 사용자 CA 설정 보존을 포함한다.
- Python의 기본 CA 경로로 GitHub TLS 검증이 실패하는 환경에서, helper 프로세스에만 OS의 CA bundle을 지정해 검증을 유지했다. 인증서 검증을 끄거나 사용자 설정을 교체하지 않았다.
- 설치 과정에서 진단 수집, 로봇 접속, JetPack/BSP 변경, DeepStream 파이프라인 실행은 하지 않았다. Codex의 스킬 재탐색은 다음 턴 또는 클라이언트 새로고침 이후 확인할 수 있다.

다른 운영체제의 심볼릭 링크 생성 권한은 검증하지 않았다. 체크아웃 이동/삭제 시 A3 링크가 깨지고 체크아웃 갱신은 설치된 A3 지침에도 반영된다. 이 설치는 합의한 자체 스킬 12개 전체의 구현 완료나 장비 동작 검증을 뜻하지 않는다.
